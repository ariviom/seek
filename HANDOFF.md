## Codebase conventions so far
- `create_app(config, transcripts, embedder, reranker, static_dir, sync_poll_seconds, events_keepalive_seconds, model_progress_seconds)`: each port is its own argument, added when its first consumer lands. Lifespan loads the models in the background and starts the `SyncWorker` task (`sync_worker.py`), which is woken on enqueue and on model state changes, and polls; it runs Syncs only while holding the `sync_lease` row, and only once the embedding model is ready (or has failed). `mentor serve` wires `YouTubeTranscriptSource` (yt-dlp, `youtube.py`, settings from `youtube_*` config) and the real models from `models.py`, sharing one `GpuRunner`.
- Models: `SentenceTransformerEmbedder` and `CrossEncoderReranker` (`models.py`) implement the `Model` port (`load()` never raises; `status()` is a `ModelStatus`) and raise `ModelUnavailable` until ready. Model statuses go out as `models` events and in Health. `uv run pytest -m real_models` runs the opt-in GPU test (models cached in `~/.cache/huggingface`; a llama-server usually holds 17 GB of the 3090).
- Search: `search.Search.search(query, group=, mentor_ids=, limit=, prefer_recent=)` is the one entry point, served at `POST /api/search` (`search_api.py`) and meant for ticket 11's MCP tool. Pure ranking steps (RRF, recency with `ranking.Recency`, matched cue) live in `ranking.py`. The Reranker port returns raw logits; recency is in the spec's "Implementation amendments".
- Live updates: `events.Events` is an in-process broker served as SSE at `GET /api/events` (`events_api.py`). Publish `sync`/`video` records after the write that changed them, or `syncs`/`videos` when a list needs reloading. The UI subscribes through `useLiveList` (or `useServerEvents` for non-lists) in `web/src/events.ts`; nothing polls.
- YouTube adapter: parsing and error classification are pure functions in `youtube.py` (tested in `tests/test_youtube.py`); the `YouTubeTranscriptSource` class only runs yt-dlp sessions, pacing and retrying Sync calls. `uv run pytest -m real_youtube` runs the opt-in live test.
- Store: `db.Database.run(fn)` runs blocking work on a thread with a fresh connection. Writes go through `db.transaction(conn)` (`BEGIN IMMEDIATE`, guarded rollback). Do read-backs inside the transaction. Migrations are appended to `db.MIGRATIONS`: additive only, never edit a shipped entry. Exception: the vec0 table `segment_vectors` and its delete trigger are created after migrations by `db.ensure_embedding_model` (dimension comes from the model), so a migration can't reference them on a fresh database.
- Sync pipeline: `videos.pipeline_stage` is the last completed stage; failure (`failure_stage` = stage attempted) and exclusion are separate columns, and the API derives a single `stage`. `SyncWorker._advance` runs each Video through its remaining stages; `videos.complete_stage` advances and clears failures. Segments are replaced per Video in one transaction; FTS5 and vec0 rows follow via triggers. Pipeline store functions return False/None when their row vanished mid-Sync (Channel deleted) rather than raising. Exclusions (minimum length plus Channel filters, bundled as `videos.ExclusionRules`) are recomputed for the whole Channel at discovery by `videos._apply_exclusions`; an excluded Video loses its Segments and steps back to `transcript_fetched`. A Sync uses the filters as they were when claimed. Retry-failed is a Sync flag (`syncs.retry_failed`) that clears failures when claimed.
- Errors: domain code raises `errors.NotFound` / `errors.Conflict`; ports raise `ChannelNotFound` / `PlaylistNotFound` (Sync-only, not in `ERROR_STATUS`) / `SourceUnavailable` / `ModelUnavailable`, and `VideoUnavailable` for one Video (reason, permanent, language, partial details). All messages are user-facing and mapped to statuses in `app.ERROR_STATUS`.
- Tests: HTTP API seam through `tests/harness.running(app)`, which runs lifespan; `harness` also has `add_mentor`, `fake_channel`, `fake_video` (optional `cues`; `date_listed=False` leaves the listing undated), `Gate` (holds a fake fetch or model load), `start_sync`, `wait_for_syncs`, `list_videos`, `fetched`, and `query` / `row_counts` for index state no API exposes yet, and `event_stream(app)` for reading SSE (httpx's ASGI transport buffers whole responses). The `embedder` fixture is a `FakeEmbedder` (`passages` records what was embedded), and the `reranker` fixture a `FakeReranker` (logit-like: 10 × share of query words present − 5; `calls`). Both load instantly and share knobs: `unavailable="..."` raises `ModelUnavailable` on calls, `load_error` fails loading, `before_load` (e.g. a `Gate`) holds loading, `status_while_loading` sets the reported progress. Every `create_app` in tests passes a `FakeReranker()`. The `client` fixture uses a seeded `FakeTranscriptSource`; it supports `unavailable="..."` for 503 cases and `playlists` for playlist filters. Listing order in a fake Channel is newest first. Pure-function tests only for intricate logic.
- UI: `web/src/api.ts` has typed calls and `errorText`. Components use Tailwind v4; shared classes and `useChanges` (a per-section busy lock that serialises changes and refreshes) live in `web/src/ui.ts`. App lifts the Mentor list from `Mentors` and the Group list from `Groups` into `Search` (and Mentors into `Groups`). Run `pnpm --dir web run build` before testing the served UI.
- Checks: `uv run pytest -q`, `uv run mypy`, `pnpm --dir web run typecheck`.
