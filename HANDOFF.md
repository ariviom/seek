## Codebase conventions so far
- `create_app(config, transcripts, embedder, reranker, chat_engine, static_dir, sync_poll_seconds, events_keepalive_seconds, model_progress_seconds, sql_time_limit_seconds)`: each port is its own argument, added when its first consumer lands. Lifespan loads the models in the background and starts the `SyncWorker` task (`sync_worker.py`), which is woken on enqueue and on model state changes, and polls; it runs Syncs only while holding the `sync_lease` row, and only once the embedding model is ready (or has failed). `mentor serve` wires `YouTubeTranscriptSource` (yt-dlp, `youtube.py`, settings from `youtube_*` config), the real models from `models.py` sharing one `GpuRunner`, and `ClaudeChatEngine` with `claude_cli_path` or else the `claude` on PATH.
- Service: `mentor install-service` (`cli.install`) calls `service.install_service(config, env, mentor_executable, unit_dir, systemctl)`, which writes `mentor.service` (the shell's PATH, `MENTOR_*` and a few location variables, the Claude CLI found on PATH as `MENTOR_CLAUDE_CLI_PATH`, `UnsetEnvironment=ANTHROPIC_API_KEY`), then daemon-reload, enable, restart; the CLI then waits for `/api/health`. Tested with an injected `systemctl` in `tests/test_service.py`. `README.md` documents install, data, every config key, agent registration, and troubleshooting; keep it current when config or setup changes.
- CLI sync: `sync_command.sync_channels(config, channel, transcripts, embedder, server_wait_seconds, poll_seconds)` probes `GET /api/syncs` on `HOST` (now in `config.py`) and hands off through `POST /api/syncs` (enqueue all indexed Channels, `syncs.enqueue_all`) or `/api/channels/{id}/syncs`; with no server it runs a `SyncWorker` in-process via `run_until_finished(sync_ids)`, which respects the lease and returns once those Syncs finish. `--channel` matches a Channel's name (case-insensitive) or YouTube channel id. `cli.sync` waits 30 s for a server when `mentor.service` is active. `install_service(..., sync_schedule=)` also writes `mentor-sync.service` (oneshot `mentor sync --all`) and `mentor-sync.timer` (`Persistent=true`); a reinstall without a schedule refreshes the sync unit's environment and leaves the timer alone. The CLI validates the schedule with `systemd-analyze calendar`. Tests in `tests/test_sync_command.py` drive `sync_channels` against `harness.serving` (up) or a free port (down).
- Remote access: `proxy.ProxyMiddleware` (added last in `create_app`, so it runs first) refuses a `Host`, `X-Forwarded-Host`, or `Origin` outside `LOOPBACK_HOSTS` plus `config.allowed_hosts` (421/403), then takes scheme, host, and `X-Forwarded-Prefix` into the scope (prefix stripped by the proxy or not; Starlette wants `root_path` inside `path`). The `web_ui` route serves index.html with `<base href="{root_path}/">`. With `cf_access_team_domain` and `cf_access_aud` set, `access.AccessMiddleware` requires a valid `Cf-Access-Jwt-Assertion` except on direct requests (loopback peer, no `X-Forwarded-*`/`Forwarded`/`X-Real-IP`/`Cf-*` headers); keys come from `create_app(fetch_access_keys=, access_keys_refetch_seconds=)`, cached hourly and refetched for an unknown kid at most that often. Tests in `tests/test_remote_access.py` sign tokens with local RSA keys (`Certs`); `harness.event_stream` takes a path and headers.
- Models: `SentenceTransformerEmbedder` and `CrossEncoderReranker` (`models.py`) implement the `Model` port (`load()` never raises; `status()` is a `ModelStatus`) and raise `ModelUnavailable` until ready. Model statuses go out as `models` events and in Health. `uv run pytest -m real_models` runs the opt-in GPU test (models cached in `~/.cache/huggingface`; a llama-server usually holds 17 GB of the 3090).
- Search: `search.Search.search(query, group=, mentor_ids=, limit=, prefer_recent=)` is the one entry point, served at `POST /api/search` (`search_api.py`) and meant for ticket 11's MCP tool. Pure ranking steps (RRF, recency with `ranking.Recency`, matched cue) live in `ranking.py`. The Reranker port returns raw logits; recency is in the spec's "Implementation amendments".
- MCP: `mcp_server.create_mcp_server` builds an `MCPServer` (mcp 2.2; FastMCP is now `mcp.server.mcpserver.MCPServer`) with `list_groups`, `search`, `expand`, `get_video`, `sql`. The grounded-advisor text is `GROUNDED_ADVISOR`, in the instructions and every tool description. `create_app` serves it stateless with JSON responses at `/mcp`, runs the session manager in its own lifespan task (anyio cancel scopes can't cross tasks), and allows loopback plus `config.allowed_hosts` as Host/Origin (the app-wide guard below checks them first). Tools raise `ToolError` for user-facing errors via `_tool_errors`; anything else reaches the client as a message-less crash. `search` reuses `search_api`'s strict field types (`SearchQuery`, `GroupRef`, `MentorIds`, `ResultLimit`) because the SDK validates tool arguments laxly. Expand and Video details live in `sources.py` (not-indexed Channels are NotFound); `GET /api/segments/{id}/expand` serves expand to the UI. `sql.run_query` is the read-only escape hatch (read-only URI, `query_only`, authorizer allowlist, progress-handler time limit, row/text/result-size and SQLite length limits).
- Web chat: `chat.Chat` runs one turn per Conversation as its own task (so it finishes and saves even if the browser leaves) and hands `chat_api` a queue, streamed as SSE with keepalives. Each turn builds `mcp_server.create_group_server(database, search, group_id)`: search fixed to the Group, expand/get_video NotFound outside it, no sql. `ChatRequest` carries that server, `GROUP_TOOL_NAMES`, and a system prompt built from `GROUNDED_ADVISOR`. `conversations.py` stores Conversations (group_id SET NULL on Group delete, group_name kept current) and messages; the question is saved before the turn, the answer on `ChatDone` with its tool calls, the session id, and Citations resolved from the answer's YouTube links (`chat.citation_links`) against the Group's searchable Videos. `claude_chat.py` holds the adapter: `chat_options` is the lockdown (tested in `tests/test_claude_chat.py`), `chat_events` maps SDK messages and strips the `mcp__mentor__` prefix; streams are closed with `contextlib.aclosing` so the CLI process stops. The web UI opens a Group's chat from its card (`web/src/Chat.tsx`, `api.sendMessage` reads the POST stream).
- Conversations: `GET /api/conversations` (`?group_id=`) lists them most recently active first (by newest message id; timestamps are only to the second) with a title from the first question, and `GET /api/conversations/{id}` returns the messages; a deleted Group leaves them read-only (409 on send). `ChatRequest.history` holds the earlier messages, replayed by the adapter when there is no session to resume; `ChatFailed.session_lost` makes `Chat` retry once without the session. `ChatEngine.status()` is the Health `claude_cli` probe (`claude auth status --json`, cached). In the UI, App holds the open chat (`opening` remounts it; a finished turn only updates the chat it came from) and a `Conversations` section refreshed by a version counter.
- Live updates: `events.Events` is an in-process broker served as SSE at `GET /api/events` (`events_api.py`). Publish `sync`/`video` records after the write that changed them, or `syncs`/`videos` when a list needs reloading. The UI subscribes through `useLiveList` (or `useServerEvents` for non-lists) in `web/src/events.ts`; nothing polls.
- YouTube adapter: parsing and error classification are pure functions in `youtube.py` (tested in `tests/test_youtube.py`); the `YouTubeTranscriptSource` class only runs yt-dlp sessions, pacing and retrying Sync calls. `uv run pytest -m real_youtube` runs the opt-in live test.
- Store: `db.Database.run(fn)` runs blocking work on a thread with a fresh connection. Writes go through `db.transaction(conn)` (`BEGIN IMMEDIATE`, guarded rollback). Do read-backs inside the transaction. Migrations are appended to `db.MIGRATIONS`: additive only, never edit a shipped entry. Exception: the vec0 table `segment_vectors` and its delete trigger are created after migrations by `db.ensure_embedding_model` (dimension comes from the model), so a migration can't reference them on a fresh database.
- Sync pipeline: `videos.pipeline_stage` is the last completed stage; failure (`failure_stage` = stage attempted) and exclusion are separate columns, and the API derives a single `stage`. `SyncWorker._advance` runs each Video through its remaining stages; `videos.complete_stage` advances and clears failures. Segments are replaced per Video in one transaction; FTS5 and vec0 rows follow via triggers. Pipeline store functions return False/None when their row vanished mid-Sync (Channel deleted) rather than raising. Exclusions (minimum length plus Channel filters, bundled as `videos.ExclusionRules`) are recomputed for the whole Channel at discovery by `videos._apply_exclusions`; an excluded Video loses its Segments and steps back to `transcript_fetched`. A Sync uses the filters as they were when claimed. Retry-failed is a Sync flag (`syncs.retry_failed`) that clears failures when claimed.
- Errors: domain code raises `errors.NotFound` / `errors.Conflict`; ports raise `ChannelNotFound` / `PlaylistNotFound` (Sync-only, not in `ERROR_STATUS`) / `SourceUnavailable` / `ModelUnavailable`, and `VideoUnavailable` for one Video (reason, permanent, language, partial details). All messages are user-facing and mapped to statuses in `app.ERROR_STATUS`.
- Tests: HTTP API seam through `tests/harness.running(app)`, which runs lifespan; `harness` also has `add_mentor`, `fake_channel`, `fake_video` (optional `cues`; `date_listed=False` leaves the listing undated), `Gate` (holds a fake fetch or model load), `start_sync`, `wait_for_syncs`, `list_videos`, `fetched`, and `query` / `row_counts` for index state no API exposes yet, `said` and `sync` for seeding searchable Videos, `mcp_client(app)` (an in-memory MCP client; open it inside a test, not a fixture, since its cancel scope can't span fixture setup and teardown), and `event_stream(app)` for reading SSE (httpx's ASGI transport buffers whole responses), and `serving(app)` to serve it over real HTTP on a free port. `tests/test_smoke.py` is the one Playwright test (Python `playwright`, Chromium from `uv run playwright install chromium`): it builds the bundle into a temp dir with vite, then adds a Mentor, Syncs, searches, and plays a search Citation and a chat Citation, asserting the iframe src with every non-server request aborted. The `embedder` fixture is a `FakeEmbedder` (`passages` records what was embedded), and the `reranker` fixture a `FakeReranker` (logit-like: 10 × share of query words present − 5; `calls`). Both load instantly and share knobs: `unavailable="..."` raises `ModelUnavailable` on calls, `load_error` fails loading, `before_load` (e.g. a `Gate`) holds loading, `status_while_loading` sets the reported progress. Every `create_app` in tests passes a `FakeReranker()` and a chat engine; the `engine` fixture is the `FakeChatEngine` the `client` fixture uses (`script` of events, or `respond(request)` to act like a model, e.g. calling `request.tools` through `mcp.Client`; `requests` records them; `engine_status` is what `status()` reports). `harness` also has chat helpers: `start_conversation`, `new_group_conversation`, `send`, `stream_events`, `done_message`, `stored_messages`, `woodworkers`. The `client` fixture uses a seeded `FakeTranscriptSource`; it supports `unavailable="..."` for 503 cases and `playlists` for playlist filters. Listing order in a fake Channel is newest first. Pure-function tests only for intricate logic.
- UI: `web/src/api.ts` has typed calls and `errorText`. Citations play in `CitationPlayer` (`web/src/Player.tsx`, a youtube-nocookie embed at the second), one at a time per view via `usePlayer`: under the result in Search, under the answer in Chat. Chat answer links play only when they match one of the message's saved Citations (`citationOf` mirrors `chat.citation_links`); a modified click still opens YouTube. The server builds watch links with `sources.watch_url`. Components use Tailwind v4; shared classes and `useChanges` (a per-section busy lock that serialises changes and refreshes) live in `web/src/ui.ts`. App lifts the Mentor list from `Mentors` and the Group list from `Groups` into `Search` (and Mentors into `Groups`). Run `pnpm --dir web run build` before testing the served UI.
- Checks: `uv run pytest -q`, `uv run mypy`, `pnpm --dir web run typecheck`.

## Environment gotchas
- The worktree guard rejects shell heredocs, `cd`-then-git chains, and setting `XDG_CONFIG_HOME` on commands. Use the Write/Edit tools for files, and keep git commands plain and separate.
- `EnterWorktree` couldn't create a worktree because the session predated `git init`. Use `git worktree add` from the main checkout, then `EnterWorktree` with `path`. Merging into `main` needs `ExitWorktree` (keep) first.
- `pkill -f <pattern>` kills your own shell if the pattern appears anywhere in that command line; run it as a command by itself.
